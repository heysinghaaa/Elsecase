# Security policy

## Supported versions

Security fixes are applied to the latest published Elsecase release and the
`main` branch. Registry consumers receive editable source, so applications
should review upstream changes before applying an update to locally modified
components.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use
[GitHub private vulnerability reporting](https://github.com/heysinghaaa/Elsecase/security/advisories/new)
and include:

- The affected registry item, route, or build process.
- Reproduction steps or a minimal proof of concept.
- The potential impact.
- Any mitigation you have already tested.

You should receive an acknowledgement within seven days. A confirmed issue will
be tracked privately until a fix and disclosure plan are ready.
